# gpu_validation_census.txt — the Metal shader-validation hits this tree accepts.
#
# `scripts/run_gpu_tests.sh` instruments every Metal pipeline and scans for
# invalid-access diagnostics. Some of them come from a kernel this repo neither
# compiles nor can fix, and failing every run on those teaches their readers to
# read `Error 1` as background noise — at which point the next real hit is
# invisible. This file is what makes the two distinguishable.
#
# ONE ENTRY PER (KERNEL, KIND, CRATE, TEST), carrying that test's own hit count
# for that kernel. A test that drives two instantiations of one template — two
# checkpoints at different bit widths, say — therefore carries one entry per
# instantiation, and the runner refuses a second entry for the same four.
#
# The runner expects, for a given (crate, kind, kernel), the sum of the counts
# whose test actually ran in this run — a test the selection dropped, or one that
# announced its own skip for want of a model, contributes 0. So a narrowed run
# and a machine with no snapshots are compared exactly, against a smaller number,
# rather than waived. Then:
#
#   * observed == expected, with no unpinned hit and no store, passes and prints
#     the census it accepted;
#   * a new kernel, a count above the expectation, a count below it, a kernel
#     that stopped firing, a hit in a different crate, or any store at all,
#     fails and names the delta.
#
# A count that came in low is a failure because a pin that drifts downward one
# hit at a time ends up describing whatever the tree does today rather than what
# was validated. Re-derive it from a full run instead.
#
# Fields, `|`-separated, six of them:
#
#   kernel    | the kernel function named in the diagnostic, verbatim
#   kind      | the access as the layer worded it (`device load`); a store is
#             | never pinnable — an invalid write is corruption, not a
#             | validated-benign read, so the runner refuses such an entry
#   count     | this test's own number of diagnostics. Derive it either by
#             | running that test alone (`make gpu-test CRATE=<crate>
#             | FILTER=<test>`), or by attributing a full run's diagnostics to
#             | the test libtest last announced — the suite runs
#             | `--test-threads=1 --nocapture`, so the `test <name> ... ` marker
#             | is the running test until the next one. The second way is what
#             | keeps a sum over entries equal to the total a full run prints.
#   crate     | the workspace member the test belongs to
#   test      | exactly one test fn name. It must be a classified GPU test, and
#             | it must print a NAMED `SKIP <test>: <why>` notice when it skips,
#             | or its count will be expected on a machine that cannot produce it
#   reference | where the analysis lives that says this hit is benign
#
# The reference field is the one place in this repo where an issue link is
# deliberate rather than forbidden: an accepted invalid access has to carry the
# evidence that accepted it, the runtime output prints that field so the reader
# never has to go looking, and a URL — unlike a bare ticket number — still
# resolves once the ticket is out of anyone's working memory.
#
# TO ADD OR CHANGE AN ENTRY you need one of two things, and nothing else counts:
# a linked upstream reference showing the defect is not ours and not reachable
# into our output, or an analysis of the same standard as the one below —
# provenance of the symbol, a load/store census over every diagnostic, and a
# demonstration that the loaded lanes do not reach the output. Neither a passing
# test suite nor a quiet run is evidence: the validation layer bounds the
# MTLBuffer rather than the array, so absence of a diagnostic is not absence of
# an out-of-bounds access.
#
# kernel | kind | count | crate | test | reference
#
# A GPU test that reaches a kernel no entry names, or that makes a load an
# existing entry does not count — a new snapshot, a new shape, a longer sweep —
# derives its own entry in the SAME change, from a run of its own. Landing it
# without one moves the failure to the next `make ci-perf` on `main`, where it
# arrives as a delta nobody can attribute. A reviewer checks the census line
# against the test the change adds or touches.
#
# The entries below are MLX's own kernels, not ones this repo compiles or can
# specialise. Every diagnostic is a device load; no store has been observed.
#
# QUANTIZED MATMUL, `*_qmm_t_splitk_*`. `QuantizedBlockLoader::load_safe` in
# `mlx/backend/metal/kernels/quantized.h` bounds its row index against the
# tile's COLUMN extent, so the guard can never fire and a transposed quantized
# matmul whose N is not a multiple of the output tile width reads the
# out-of-range rows of the packed weight and the scales. rMLX passes correctly
# sized operands.
#
# The loaded lanes do not reach the output, and the reason is structural rather
# than a bit width or a loader that happened to be measured: `tile_matmad`
# computes y[m][n] = SUM_k Xs[m][k] * Ws[n][k], so there is no reduction across
# n and no path from a poisoned Ws row into a kept column, and the store then
# clips to num_outs. The argument names neither `bits` nor the affine or mxfp8
# dequantisation, which is what carries it across the instantiations pinned
# here. The measurements corroborate it: the wrong selector reports at affine
# bits 2, 3, 4, 5, 6 and 8 across group sizes 32, 64 and 128 (18 of 18 cells),
# the output-reachability arms were run at bits 2 and 8, and
# `rmlx-mlx`'s `split_k_tail_row_reads_never_reach_the_output` multiplies one
# kept row from its own buffers and from views whose tail rows are NaN, or
# varied values up to +-3e4 whose quantized codes are asserted non-zero,
# bit-identical at affine b4, affine b8 and mxfp8 gs32 b8, the three
# instantiations below. The selector is identical in the next MLX
# release, so moving the pinned MLX does not remove it.
#
# IMPLICIT-GEMM CONV, `implicit_gemm_conv_2d_float32_*_channel_l_filter_s`. The
# weight loader in `loader_channel_l.h` checks the output-channel bound only for
# 8-wide N tiles (`if (BN != 8 || do_read)`); with a 64-wide tile a 96-channel
# weight has its second tile read rows 96..127. Each output channel is computed
# from its own weight row only and the store clips channels at or above 96.
# `rmlx-mlx`'s `implicit_gemm_conv_tail_channel_reads_never_reach_the_output`
# is bit-identical with the tail rows at NaN, +3e4 and -3e4.
#
# The buffer length beside each diagnostic is the MTLBuffer MLX allocated from a
# size bucket, not the tensor, so it does not identify the operand; the
# argument above does not depend on which operand overruns. In the run below,
# per kernel and length in `rmlx-models`:
#
#   affine b_4    7680: 3077   8192: 4590   8960: 26   9216: 43   9344: 25
#                 131072: 687
#   affine b_8    2048: 2136   3072: 1733
#   mxfp8 b_8     7680: 3168
#
# DERIVED ON a full `make gpu-test`, every diagnostic attributed to the test
# libtest last announced, on a host holding every snapshot the suite resolves by
# slug, with threadgroup-memory validation split per test
# (`scripts/gpu_test_threadgroup.sh`) — every entry below comes from a test that
# ran with it off. Two full runs, the second after the split was keyed on the
# kernel a test names, attributed the same count to every entry. Fifteen cells
# stood down for want of `RMLX_KV_TEST_MODEL`, `RMLX_VL_TEST_MODEL`,
# `RMLX_PROMPT_CACHE_TEST_MODEL_A` or `RMLX_TEST_MODEL_JINA_V4`, and pin
# nothing; a run that arms one of them reports its hits as deltas until the pin
# is derived again. Totals: 8448 affine `b_4`, 3869 affine `b_8` and 3168
# mxfp8 `b_8` in `rmlx-models`; 4 of each split-K and 4 conv in `rmlx-mlx`; 3
# conv in `rmlx-audio`.
#
# A test that sweeps two checkpoints carries one entry per instantiation. On a
# host holding one of them, that test still runs and the absent one's entry
# reports `no longer fires`: the entry key has no room for which checkpoint
# produced the count, and a red that names the missing model is the intended
# outcome there.
