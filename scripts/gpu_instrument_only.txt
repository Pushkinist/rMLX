# gpu_instrument_only.txt — the GPU tests this tree accepts as failing under
# Metal shader validation and passing without it.
#
# `scripts/run_gpu_tests.sh` takes each test's verdict from a run with no
# instrumentation, because the instrument can change what an MLX kernel
# computes. That alone would accept too much: a kernel defect that only the
# instrument's timing or memory layout exposes fails under validation, passes
# without it and prints no diagnostic, exactly as an artifact of the instrument
# does. So a test is accepted in that state only when an entry here names it and
# refers to the analysis that says the instrument is the cause.
#
#   * a test that fails only under the instrument and has an entry is listed,
#     and the run ends INCOMPLETE: its scan stopped at the failure;
#   * one with no entry is a failure, `not pinned: …`;
#   * an entry whose test the scan ran to its end, green, is a failure,
#     `stale: …`. Delete the entry.
#
# An entry whose test was not selected, or stood down, says nothing.
#
# Fields, `|`-separated, three of them:
#
#   crate     | the workspace member the test belongs to
#   test      | exactly one classified GPU test fn name
#   reference | where the analysis lives
#
# TO ADD AN ENTRY you need a reproduction outside rMLX that shows the result
# changes with the instrument alone, or a statement in the reference of what
# is not yet shown. A passing uninstrumented run is not evidence: that is the
# state every entry here is in.
#
# NO ENTRY. No test of this tree fails only under the instrument. The one
# kernel known to change under it, MLX 0.32.3's head-dim-split attention
# kernel with unaligned query and key rows, receives no call from rMLX
# (docs/FFI.md, "scaled_dot_product_attention").
#
